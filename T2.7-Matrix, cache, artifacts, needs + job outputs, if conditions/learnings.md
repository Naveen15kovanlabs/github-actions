# Learnings – T2.7: Matrix, Cache, Artifacts, Needs + Job Outputs, If Conditions

While working on this task, I learned how to use different GitHub Actions features to make workflows more organized, reusable and efficient.

## 1. Matrix Strategy

- Learned how to use matrix strategy to run the same test job with multiple Python versions.
- Instead of creating separate jobs manually, I can define the versions in a matrix.
- GitHub Actions automatically creates separate jobs and runs them in parallel.

**What I understood:** Matrix strategy is useful when I need to test an application across multiple Python versions or operating systems.

## 2. Dependency Caching

- Learned how GitHub Actions caching works with Python dependencies.
- Used `actions/setup-python@v5` with pip caching.
- Understood how previously downloaded packages can be reused in future workflow runs.
- Verified cache restoration through the workflow logs using `Pip cache hit: true`.

**What I understood:** Caching helps reduce unnecessary dependency downloads and can improve workflow execution time.

## 3. Artifacts

- Learned how to upload files generated during workflow execution.
- Used `actions/upload-artifact@v4` to upload pytest XML reports.
- Generated separate reports for Python 3.11 and Python 3.12.
- Verified that both reports were available in the GitHub Actions Artifacts section.

**What I understood:** Artifacts are useful for storing test reports, build outputs and other files that I may need after a workflow finishes.

## 4. Needs and Job Outputs

- Learned how to control the execution order of multiple jobs using `needs`.
- Understood how one job can wait for another job to complete.
- Used job outputs to pass Python version information from the prepare job to the matrix testing job.
- Learned how to access values generated by one job in another job.

**What I understood:** `needs` manages job dependencies, while job outputs help share information between jobs.

## 5. If Conditions

- Learned how to use `if` conditions to control whether a job or step should execute.
- Understood how workflow inputs and previous job results can be used in conditional expressions.
- Used conditions to control test execution based on the selected workflow input.

**What I understood:** Conditions help avoid unnecessary job execution and give more control over workflows.

## 6. Pros and Cons

### Pros

- Matrix strategy avoids creating duplicate jobs manually.
- Parallel execution helps complete multiple tests without waiting for each one sequentially.
- Caching reduces repeated dependency downloads.
- Artifacts make it easy to access test reports after workflow execution.
- `needs` helps maintain a proper execution order between jobs.


### Cons

- Matrix strategy can increase GitHub Actions usage because multiple jobs are created.
- Caching requires proper cache keys and dependency file configuration.
- The first workflow run may take longer because the cache needs to be created.


## 7. Practical Observations

- Successfully executed matrix testing using Python 3.11 and Python 3.12.
- Verified that the dependency cache was restored successfully.
- Uploaded and verified two pytest report artifacts.
- Checked individual job execution times through the GitHub Actions Usage section.
- Understood that cache restoration does not automatically mean the entire workflow will become faster.
- Need to perform a controlled cold-cache and warm-cache comparison to confirm the actual reduction in dependency installation time.

## Final Takeaway

This task helped me understand how different GitHub Actions features work together in a single CI workflow.

I got practical experience with matrix builds, caching, artifacts, job dependencies, outputs and conditional execution.

I also learned that workflow optimization is not just about implementing caching but also about checking execution logs, comparing timings and verifying whether the changes actually improve performance.
